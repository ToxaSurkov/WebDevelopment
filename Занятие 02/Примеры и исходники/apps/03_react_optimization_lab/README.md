# Лаборатория оптимизации React (занятие 2)

Три рабочих примера: (1) повторный рендер дочернего компонента, сравнение обычного компонента и `React.memo`; (2) дорогое вычисление и `useMemo`; (3) отложенная загрузка `React.lazy` + `Suspense`.

## Запуск

```bash
npm install
npm run dev
```

Откройте показанный адрес `localhost`. При наличии зависимостей проверьте production-сборку:

```bash
npm run build
npm run preview
```

## Демонстрация 1 — React.memo

1. Откройте вкладку «Рендеры» и DevTools → Console.
2. Несколько раз нажмите «Увеличить счётчик». Обычный дочерний компонент повторно рендерится, хотя его props не меняются.
3. Переключите режим на `React.memo` (первый рендер новой карточки происходит нормально) и ещё несколько раз нажмите «+1»: счётчик её рендеров остаётся прежним.
4. Покажите DevTools → Components/Profiler, включите запись, нажмите кнопку и закончите запись. Поясните, что рендер компонента — не обязательно изменение реального DOM.

## Демонстрация 2 — useMemo

1. Откройте вкладку «Вычисления». Две колонки показывают, сколько чисел из одного набора подходят под условие `число >= порог` и сколько раз выполнялся перебор.
2. При пороге 600 нажмите «Обновить экран» три раза. Число совпадений сохранится. Счётчик расчётов слева вырастет с 1 до 4, справа останется 1.
3. Сдвиньте порог с 600 на 700. В обеих колонках будет 53 820 совпадений и по одному новому расчёту.
4. Сравнивайте счётчики расчётов. Время в миллисекундах показывает длительность последнего выполненного расчёта и может колебаться.

## Демонстрация 3 — React.lazy

1. Обновите страницу на вкладке «Загрузка кода», откройте Network и очистите список.
2. Нажмите «Открыть статистику»: браузер запрашивает отдельный модуль `LazyStatistics.jsx` (в dev) или соответствующий chunk JS (в production).
3. После первой загрузки модуль может остаться в кэше. Для повторения обновите страницу и используйте Disable cache в DevTools.

## Важно

- Лаборатория намеренно НЕ включает React Compiler, чтобы наглядно сравнить ручную мемоизацию. В современных проектах Compiler может сокращать потребность в `memo`/`useMemo`, но требует конфигурации сборки.
- Искусственная вычислительная нагрузка создана для демонстрации. Она **не доказывает**, что оптимизация нужна реальному каталогу из 60 записей.
- `React.memo` не гарантирует отсутствие всех рендеров: внутренний state, context и изменившиеся props могут вызвать обновление.
- В этом учебном примере React StrictMode намеренно не включён для упрощения сравнения числа рендеров. В обычных проектах его отключать ради производительности не следует.
- Эта лаборатория отдельная от двух исходных проектов; студенческая задача их доработки остаётся без готового решения.
