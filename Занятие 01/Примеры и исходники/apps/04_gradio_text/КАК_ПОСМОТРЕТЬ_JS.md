# Как показать студентам JavaScript внутри Gradio и Streamlit

## Главное различие

**Файл `app.py` обычно не превращается в отдельный читаемый `app.js`.** Python-код выполняется на стороне сервера. Браузер получает готовые JavaScript-модули и CSS, которые поставляются в составе библиотеки, плюс конфигурацию интерфейса и данные. Поэтому название и содержимое JS-бандлов зависят от установленной версии Gradio/Streamlit.

У Gradio frontend использует, в частности, компоненты Svelte. У Streamlit frontend работает в браузере, а обмен состоянием с Python-сервером происходит через постоянное соединение WebSocket (в актуальной архитектуре). Наши учебные Python-функции `analyze()` **по умолчанию не переводятся в JavaScript**: они вызываются на Python-сервере.

Это не исключает пользовательского JavaScript и специальных client-side функций в современных версиях некоторых библиотек — но в **наших** примерах этого нет.

## Gradio: что показать (5 минут)

1. В терминале перейти в `apps/04_gradio_text`.
2. Установить пакеты (один раз): `python -m pip install -r requirements.txt`.
3. Запустить `python app.py`. Наш пример открывается по **http://127.0.0.1:7860/**.
4. В Chrome нажать **F12** → **Network**, включить `Disable cache` при открытых DevTools, обновить страницу **Ctrl+R**.
5. Нажать фильтр **JS** (или выбрать `All` и найти ресурсы с `.js`). Это **реальные файлы JavaScript, загружаемые браузером**. В разных версиях имена могут выглядеть как хешированные файлы в `/assets/`.
6. Открыть один JS-ресурс → **Response**. Он может быть минифицированным. Во вкладке **Sources** выбрать файл и нажать **`{}` (Pretty print)**, чтобы сделать форматирование читабельнее.
7. Вернуться во вкладку **Network**, нажать кнопку обработки/отправки в интерфейсе Gradio и посмотреть **Fetch/XHR** или **EventStream** (тип обмена зависит от версии и механизма исполнения). В Python-файле найти `fn=analyze` и открыть определение `def analyze(text: str)`.

**Что сказать:** код интерфейса исполняется браузером; функция `analyze()` — Python-код на сервере; Gradio связывает их без необходимости писать сетевой код вручную.

## Streamlit: что показать (5 минут)

1. Перейти в `apps/05_streamlit_text`.
2. Установить пакеты: `python -m pip install -r requirements.txt`.
3. Запустить `python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501`.
4. Открыть **http://127.0.0.1:8501/** → DevTools **F12 → Network**, обновить страницу.
5. В фильтре **JS** посмотреть загружаемые `.js`-ресурсы. Если они минифицированы, в **Sources** использовать **`{}` (Pretty print)**.
6. Переключить вкладку Network в фильтр **WS**, выбрать подключение WebSocket, открыть **Messages**. Отображение может быть бинарным (например, protobuf) и не обязано быть удобочитаемым — для лекции достаточно показать само соединение.
7. Изменить содержимое текстового поля или нажать кнопку. Параллельно в `app.py` обратить внимание на `st.text_area`, `st.button` и `result = analyze(text)`. По умолчанию изменение виджета приводит к повторному запуску Python-скрипта; при этом frontend обновляется в браузере.

**Что сказать:** Python описывает содержимое UI через `st.*`, а браузер получает готовый клиент Streamlit, который показывает интерфейс и передаёт пользовательские действия серверу.

## Если нужны именно URL загруженных JS-файлов

Откройте в DevTools вкладку **Console**, вставьте и выполните:

```javascript
performance.getEntriesByType('resource')
  .map(resource => resource.name)
  .filter(url => /\.js(?:[?#]|$)/i.test(url));
```

Это список **части загруженных JS-ресурсов** (зависит от браузера, кеширования и версии). Ещё один вариант — `Network → JS`.

Откройте конкретный URL из списка в соседней вкладке, затем `Ctrl+S`, если хотите сохранить **один реальный библиотечный JS-файл** для офлайнового показа. Сохранять полные сборки библиотек в архив наших маленьких приложений не стоит: файлы велики, минифицированы и меняются при обновлении версии.

Не экспортируйте в общий доступ HAR-записи реальных аккаунтов: они могут содержать токены, cookies и отправленные пользователем данные. Для лекции используйте только наши локальные примеры.

## Можно ли показать разницу в исходниках?

Наш `apps/02_browser_text/index.html` сам содержит написанный нами JavaScript: `document.getElementById(...)`, `addEventListener(...)`, `analyze(text)`. Он понятен и годится для чтения с аудиторией.

В `apps/04_gradio_text/app.py` и `apps/05_streamlit_text/app.py` мы пишем на Python. Библиотеки подгружают готовый фронтенд. Поэтому на занятии **полезнее одновременно показать три окна**: Python в редакторе, интерфейс в браузере и Network/Sources в DevTools.
